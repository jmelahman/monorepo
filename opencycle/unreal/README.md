# OpenCycle in Unreal

OpenCycle's ride in Unreal Engine 5.8: a fictional Japanese countryside, generated by the scripts
here and ridden by the `OpenCycleUE` C++ module. Everything runs in the `unreal` container as `ue4`,
with the DDC at `/workspace/ddc`.

## Where things live

Git holds the source: `scripts/`, the module in `OpenCycleUE/Source`, the project file and its
`Default*.ini`, and `tests/`. The working project is `/workspace/ue`, outside git, because its
`Content/`, `assets_gen/`, downloads and renders run to tens of gigabytes. It reaches the source
through symlinks: `scripts`, `README.md`, `OpenCycleUE/OpenCycleUE.uproject`, `OpenCycleUE/Source`
and `OpenCycleUE/Config/Default{Engine,Game,Input}.ini`.

`/workspace/ue/local.env`, when present, makes `coast_rebuild.sh` and `coast_ride.sh` render light:
thinner scatter (`OC_DENSITY`), 720p and a frame-rate cap, for an integrated GPU that also drives
the desktop and resets on full-density frames. A GPU pod has no copy and renders in full.

## Playing the ride

`ARidePawn` carries the rider along the path at the speed their power gives (`RidePhysics.h`), with
the camera the stills use, the weather following where they are and the rain carried round them.
For now power comes from the keyboard: W or Up adds watts, S or Down takes them away. The track comes
from `/Game/Coast/Ride/DA_RideTrack`, which `ride_track.py` writes.

A ride opens on a start screen that picks where power comes from. Esc, P or Space pauses, and the
pause menu resumes, goes back to the start, or quits. Both reach the video settings: an overall
quality, the scalability groups one by one, render scale, a frame-rate cap, VSync and the window,
applied at once and kept in the engine's `GameUserSettings.ini`. `URideMenu` builds all three pages
in C++, with no Blueprint asset, and `ARidePlayerController` opens it. A ride started with
`-RideStart`, `-RideWatts`, `-RideShots` or `-RideNoMenu` skips the menus and renders at Epic,
whatever the player chose, so stills and tests don't change with someone's settings.
`ARideHUD` shows speed, power, cadence, heart rate, grade, distance and time, a map of the course
and its height profile.

Smart trainers come in three layers, the first two plain C++ that `tests/run.sh` checks without the
engine. `BleProtocol.h` reads and writes the Bluetooth packets: heart rate, cycling power, speed and
cadence, and FTMS indoor bike data and control. `BleSession.h` takes control of an FTMS trainer,
sends it the grade when it moves, and picks the best source for each reading. `BleTrainer.h` puts a
session behind `ITrainer` over an `IBleLink`. The only link so far is `FSimulatedLink`
(`-RideTrainer=sim`), which plays a trainer from the keyboard's watts; the radio link needs D-Bus
and BlueZ, which this container doesn't have.

The packaged game turns off PSO precaching (`DefaultEngine.ini`): Mesa 25.0's ACO aborts compiling
one of the precached pipelines.

```sh
# Build the module (UBA crashes clang in this container, hence -NoUBA).
sudo -u ue4 env HOME=/home/ue4 ~ue4/UnrealEngine/Engine/Build/BatchFiles/Linux/Build.sh \
    OpenCycleUEEditor Linux Development -Project=/workspace/ue/OpenCycleUE/OpenCycleUE.uproject -NoUBA
bash scripts/ue_run.sh ride_track.py ride_track.log    # after make_coast.py, or the path changes
bash scripts/play.sh                                   # ride it in the editor's -game mode
bash scripts/package.sh                                # a standalone Linux build in out/package
bash scripts/ride_test.sh 250 15,45 0 -RideTrainer=sim  # offscreen: watts, shot times, start metres
OC_TOUR=1 bash scripts/ride_test.sh                     # offscreen: screenshot each menu page
tests/run.sh                                           # physics and Bluetooth, without the engine
```

## Rides

- **Forest** (`make_forest.py`, `make_ride.py`): the first test ride, through a Poly Haven forest.
- **Coast** (the `coast_*` and `make_*` scripts listed below): a fictional Japanese countryside, about 2.2 km long.
  A narrow lane runs through a small town, then between rice paddies, through a jungle with
  bamboo and a shrine, and along a sea wall under a mountain. Riders keep left.

## Building the coast ride

Run the steps in order. A step needs to run again only when its inputs change.

```sh
# 1. Generate the geometry with system Python (no Unreal needed).
python3 -I scripts/make_terrain.py          # assets_gen/terrain: near and far tiles, then the sea
python3 -I scripts/make_paths.py            # assets_gen/paths: the lane, kerbs, gutters, rail, poles and wires
python3 -I scripts/make_houses.py           # assets_gen/kit: ten houses and the street kit
python3 -I scripts/make_bamboo.py           # assets_gen/kit/K_bamboo_*, plus the leaf texture
python3 -I scripts/make_sugi.py             # K_sugi_* (cedar) and K_matsu_* (pruned garden pines), plus their card
python3 -I scripts/make_wave.py             # textures/sea_waves_nor_dx.png

# 2. Import into the project. These steps are long.
OC_STAGE=models bash scripts/ue_run.sh coast_assets.py coast_assets_models.log   # Poly Haven models
OC_STAGE=sea,terrain bash scripts/ue_run.sh coast_assets.py coast_assets_terrain.log
OC_STAGE=terrain_material bash scripts/ue_run.sh coast_assets.py retex.log   # rebuild M_Terrain only, no reimport

# 3. Build the level /Game/Coast/L_Coast. OC_REIMPORT=1 re-imports the generated kit.
bash scripts/ue_run.sh make_coast.py make_coast.log
bash scripts/ue_run.sh coast_fixup.py coast_fixup.log   # always after make_coast: see Pitfalls

# Steps 3 and 4 (stills) in one go; OC_RETEX=1 also rebuilds the terrain material first.
OC_REIMPORT=1 OC_OUT=out/coast_v5 bash scripts/coast_rebuild.sh

# 4. Render.
OC_MODE=stills bash scripts/coast_ride.sh                            # out/coast/still_NN.png, one per zone
OC_FROM=400 OC_SECONDS=10 OC_OUT=out/paddies bash scripts/coast_ride.sh   # a 10 s clip of frames
```

### Settings for `coast_ride.sh`

| Variable | Meaning | Default |
| --- | --- | --- |
| `OC_STILLS` | Shots, as `metres[:yaw[:pitch[:lateral[:eye]]]]` joined by commas | `50,300,550,900,1300,1700,2050` |
| `OC_FROM` | Where a clip starts, in metres | 0 |
| `OC_SECONDS` | Length of a clip | 10 |
| `OC_SPEED` | Riding speed, in m/s | 7 |
| `OC_EYE` | Camera height, in cm | 150 |
| `OC_FOCAL` | Lens focal length, in mm | 16 |
| `OC_RES` | Output resolution | `1920x1080` |

### Settings for `make_coast.py`

| Variable | Meaning | Default |
| --- | --- | --- |
| `OC_SUN` | Sun pitch,yaw | `34,-62` |
| `OC_SUN_LUX` | Sun brightness, in lux | 90000 |
| `OC_FOG` | Fog density | 0.006 |

## Pitfalls

- **Winding in `gltf_writer`.** Give each face's corners so that the cross product `(b-a)×(c-a)` points out of the face, in UE axes. The writer reverses the order for glTF.
- **`flip_winding.py`.** It only fixes tiles written before the fix in `make_terrain.py`. Run it once per file, never twice.
- **Importing helpers.** Helpers load with `sibling()` rather than through `sys.path`. Otherwise the folder's `inspect.py` shadows the standard library's.
- **Poly Haven foliage.** Its normal maps are OpenGL style, so the master material flips green. Its alpha comes from a separate PNG.
- **Interchange finishes late.** It overwrites a mesh's material slots after the import call returns,
  so slots set by `make_coast.py` don't stick. `coast_fixup.py` assigns them afterwards, by slot name,
  and flags every base material for Nanite and instancing. Without the flags `-game` renders the checker.
- **`mask()` sets all four channels.** A new ComponentMask starts with R and G on.
- **Single Layer Water** needs `ScatteringCoefficients` and `AbsorptionCoefficients` connected.
- **Poly Haven grass is dry litter.** The terrain takes only its brightness and tints it green.
- **Memory.** Imports take about 17 GB of the machine's 30; run one Unreal at a time.
- **UBA.** The Unreal Build Accelerator's file hooks segfault clang in `opendir` here. Build with `-NoUBA`.
